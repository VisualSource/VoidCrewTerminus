Upgrade Forge — Texturing & Material Guide

How to get from a Blender mesh (UpgradeForge.blend) to a working HDRP/Lit material in VoidCrewUnityEditor. Written after tracking down why UpgradeForgeModuleCell rendered near-black: the mesh, UVs, and lighting were fine the whole time — the material was missing a Mask Map, so Metallic was effectively undefined. Companion to upgrade-forge-prefab-authoring.html.

What HDRP/Lit actually needs

HDRP/Lit reads up to four textures per material. Only the first is required to see the mesh at all; the rest control how it responds to light.

SlotFieldColor spaceWhat it drives
Base Map_BaseColorMapsRGBDiffuse albedo. Alpha channel is unused on an opaque material.
Mask Map_MaskMapLinearPacked: R=Metallic, G=Ambient Occlusion, B=Detail Mask, A=Smoothness. One texture, four independent grayscale channels.
Normal Map_NormalMapLinear (auto-flagged "Normal map")Tangent-space surface detail. Unity expects OpenGL convention (+Y green channel) — Blender's default bake matches this.
Detail Map_DetailMapLinearOptional close-up micro-detail, tiled independently of the base UVs. Skip it unless the surface needs it.
The actual bug With no Mask Map assigned, Metallic falls back to the flat _Metallic slider value with no matching Smoothness/AO data to go with it. If that slider isn't at 0, HDRP treats the surface as reflective metal with nothing correct to reflect — the result reads as near-black under normal lighting. This is exactly the gap in the project's current Assets/Mods/VoidCrewTerminus/Materials/TestMat.mat: it has a _BaseColorMap but empty _MaskMap/_NormalMap slots. Either assign a real Mask Map or drop Metallic to 0 and rely on the Smoothness slider alone.

1 · Preparing the model in Blender

  1. UV unwrap first. Every texture below is a 2D image sampled through the mesh's UVs — baking or painting is pointless without a clean, non-overlapping unwrap (U → Smart UV Project or manual seams in the UV Editing tab). Check for overlaps with UV Editing → UV → Stats.
  2. Build (or reuse) the shading material in Blender's Shading tab. A Principled BSDF maps almost 1:1 onto HDRP/Lit: Base Color → Base Map, Metallic → Mask Map red, Roughness → invert into Mask Map alpha (Smoothness = 1 − Roughness), Normal → Normal Map.
  3. For a hand-painted look (no procedural shader), paint directly in Texture Paint mode on a new image per channel you need (Base Color, Roughness, Metallic, AO).

Baking the textures

In the Shading tab, add an Image Texture node per output, select it (so it's the active bake target), then Render Properties → Render Engine: Cycles → Bake:

Bake typeFeedsNotes
Diffuse (Color pass only)Base MapUncheck Direct/Indirect, keep only Color — otherwise you bake in scene lighting.
RoughnessMask Map alphaBakes as grayscale; invert in GIMP/Photoshop before packing (Smoothness = 1 − Roughness).
NormalNormal MapSpace: Tangent. Blender's default (+Y, OpenGL) needs no channel flip for Unity.
AOMask Map greenBake with the built-in AO pass (tune the Distance value — see below), or leave this channel flat white (255 = no occlusion) if you don't need it yet.
Metallic valueMask Map redNot something you bake — it's a material-classification mask. Paint white only where the surface is genuinely bare/exposed metal; black everywhere else (paint, plastic, rubber, glass, decals). See below before flat-filling this one.
Note If the model is a simple hard-surface panel with one uniform material (no high-poly detail to bake down), you often don't need Cycles baking at all — flat-color fills for Metallic/AO and a hand-painted or tileable Base Color/Normal are enough. Save the full bake workflow for parts that need actual surface variation.

Getting a soft AO gradient (not hard black/white)

A naive AO bake tends to clip to almost pure black-or-white with barely any gradient in between — measured on UpgradeForgeModuleCell's first AO pass, over half the pixels sat at exactly 0 (median = 0), which reads as large flat panels going fully black regardless of whether they're actually enclosed. The fix is an occlusion-distance cutoff: without one, distant unrelated geometry across the whole mesh contributes to the occlusion test, blowing out big flat surfaces that shouldn't be occluded at all.

  1. In recent Blender versions the old Bake → Ambient Occlusion → Influence → Distance checkbox (and the legacy World Properties → Ambient Occlusion panel) may not be present. The reliable, version-proof alternative: use the Ambient Occlusion shader node directly (Shading tab → Add → Input → Ambient Occlusion). It carries its own Distance input value regardless of where Blender moves the panel-based settings.
  2. Plug that node into an Emission shader's Color input, wire the Emission into Material Output (temporarily, in place of your normal shader), select your bake target image, and set Render Properties → Bake → Bake Type to Emission (this may be labeled Emit in older versions).
  3. Tune the AO node's Distance relative to the model's scale — start small (e.g. 0.1–0.5m) and increase until real crevices/corners read as occluded without flattening large open panels to solid black. Re-bake after each change.
  4. Undo the Emission wiring once you're happy with the result, and restore the normal shader graph.
Sanity check After tuning Distance on this mesh, mean brightness rose from ~29% to ~38% and the median moved from 0 to 43 — i.e. it stopped being "more than half the image is pure black." Standard deviation barely changed (~110 → ~107), which is expected and fine: a hard-surface panel legitimately has true-white flats and near-black creases, just with a real transition between them instead of a hard clip.

Authoring the Metallic mask

Don't derive this from the Base Color texture's brightness or grayscale value — albedo color and metalness are unrelated properties. A dark-gray painted panel and a dark-gray raw metal panel can share nearly identical albedo while needing opposite Metallic values, so desaturating the base texture into a metallic mask just encodes color luminance, not material type.

Default matters If you don't have time to hand-paint a proper per-region mask yet, default this channel to flat black (0), not white. A flat-white Metallic map (as ModuleExterior_Mask.png currently packs, sourced from a flat-white Metallic.png) tells HDRP the entire hull — paint, trim, everything — is bare conductive metal, which kills its diffuse response and makes it depend entirely on environment reflection for lighting. Treating a coated hull as fully non-metallic by default is the more plausible baseline; paint in white later only for the specific exposed-metal details (edges, bolts, vents) once doing a real detail pass.

2 · Packing the Mask Map

HDRP has no separate "Metallic map" or "Smoothness map" slot — everything lives in one RGBA texture. Two ways to build it:

  1. Unity's built-in packer (easiest). Open the material, click the small texture-slot dropdown next to Mask Map in the HDRP/Lit Inspector → Create Mask Map. It opens a wizard with one texture picker per channel (Metallic, Occlusion, Detail Mask, Smoothness) and bakes them into a single new texture asset for you — no external image editor needed.
  2. Manual packing (GIMP/Photoshop). Create a new RGBA image at the same resolution as the source grayscale maps. Paste Metallic into the Red channel, AO into Green, leave Blue black (no detail mask) unless authoring one, and Smoothness into Alpha. Export as PNG.

For reference: a known-good vanilla Void Crew metal material (Metal_Grey_Mat) ships with Mask Map, Normal Map, and Detail Map all populated, plus a mid-gray Base Color tint (~0.57, 0.57, 0.57) rather than pure white, tiled 4× over the mesh UVs. That's a reasonable target to match for a plain metal panel.

Gotcha Getting sRGB wrong on the Mask Map is a quiet failure — no error, just wrong-looking metal/roughness response, since the values get gamma-corrected when they shouldn't be. If a baked/packed metal surface looks subtly off despite the right channels being present, check this checkbox first.

Set the Normal Map's Texture Type to Normal map explicitly — don't rely on the "Create from Grayscale" fallback for a texture that's already RGB normal data.

4 · Assigning to the material

  1. Drag each texture into its matching slot (Base Map, Mask Map, Normal Map, Detail Map) on the HDRP/Lit material.
  2. Assigning a texture should flip the matching shader keyword automatically (e.g. _MASKMAP once Mask Map has a texture). If a slot has a texture but the surface still behaves like it's missing, check the material's serialized m_ValidKeywords in the .mat YAML — a stale keyword list (left over from copy-pasting a different material) can desync from what's actually assigned.
  3. With a Mask Map assigned, the Metallic and Smoothness sliders on the material become remap ranges for the texture's R/A channels, not flat overrides — leave them at their defaults (Metallic remap 0–1, Smoothness remap 0–1) unless you're deliberately compressing the range.

5 · The simplest material for testing

Before investing in a full PBR texture set, use this to isolate mesh/UV/lighting problems from material problems — exactly the test that found this bug in the first place.

  1. Create a new Material, shader HDRP/Unlit (not HDRP/Lit).
  2. Set Color to something saturated and unmistakable (e.g. solid magenta or lime).
  3. Optionally drag in just the Base Color texture — HDRP/Unlit ignores lighting entirely, so this shows raw UVs/texture placement with zero risk of a lighting or Mask Map issue muddying the result.
  4. Apply it to the mesh. If it renders as flat, correctly-mapped color: mesh and UVs are confirmed good, and any remaining "black mesh" symptom is 100% a HDRP/Lit material configuration issue, not geometry.
Then graduate Once the Unlit test confirms the mesh is fine, switch the same material's shader back to HDRP/Lit in the Inspector (Unity keeps the Base Color/texture assignment across the switch), leave Mask Map/Normal Map empty, and set Metallic to 0. This should look flat but lit — a plain matte gray/colored surface reacting normally to scene lights, no black patches. That's the baseline to build the real PBR textures on top of, one slot at a time (Normal Map first, then Mask Map), re-testing in-game after each addition.

6 · Verify in game

  • Test in the actual game scene, not Prefab Isolation Mode — isolation view uses its own fixed preview lighting rig and will not reflect real in-game results.
  • Full game restart between iterations if testing via the exported .metem bundle; AssetLoader's HasAsset guard can mask a stale reload otherwise.
  • Compare against a known-good vanilla material (copy one onto a spare mesh) any time a result looks ambiguous — this is the fastest way to tell "my material is misconfigured" from "something else is wrong."
